# Migration Guide: v1.0.9 to v1.1.0 (STABLE)

ResearchBench v1.1.0 is a major stabilization release focusing on mathematical correctness, reproducibility, memory safety, and honest reporting.

## 1. Deprecated Fake Artifact Checks
* The rtifact_audit system in v1.0.9 used naive OCR and string matching to verify methodology (e.g. checking if "{folds}-fold" existed in the PDF). This was technically invalid and has been **deprecated**.
* v1.1.0 introduces a structured semantic consistency engine using optional local LLMs. If an LLM is unavailable, it honestly reports that it is performing a deterministic fallback.

## 2. Conformal Behavior Changes
* v1.0.9 calculated empirical quantiles based on Out-of-Fold (OOF) CV predictions. This violated exchangeability. 
* v1.1.0 implements **true Split-Conformal Prediction**. Prediction intervals generated by v1.0.9 are methodologically invalid and should not be used for rigorous publication. v1.1.0 bounds will differ but are mathematically defensible.

## 3. Balancing Behavior Changes
* v1.0.9 injected class_weight="balanced" blindly. This silently failed for Ensembles and nested pipelines.
* v1.1.0 safely injects the parameter only if supported by the underlying estimator.

## 4. Sparse Preprocessing Behavior
* **CRITICAL:** v1.0.9 forced OneHotEncoder and TfidfVectorizer to densify sparse matrices (e.g., .toarray()), which caused OOM crashes on large datasets.
* v1.1.0 preserves sparse matrices through the pipeline. A memory safety guard aborts execution if densification is required and exceeds a configurable limit (default: 2GB).

## 5. Model Registry Additions
* XGBoost, LightGBM, and CatBoost are now available if installed. Use xgboost, lightgbm, or catboost in your models list.

## 6. Interactive Visualizations
* The static base64 matplotlib PNGs have been replaced by offline-capable interactive plotly JSON objects injected into the HTML report.
